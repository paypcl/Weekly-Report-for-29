# MySQL-多表

## 一、多表设计

主要有三种形式：一对多，多对多，一对一；

一般两张表连接时，是通过**主键** 建立联系，这样可以防止因为用户修改数据等失去映射关系；

### 1.一对多-外键约束

两张表，只是通过一个主键建立联系的话，在数据库层面并未建立关联，所以是无法保证数据的一致性和完整性的

#### 物理外键（不推荐

使用`foreign key`定义外键关联另外一张表；

即多的一方添加外键指向一；

但是缺点也很明显：1、影响增、删、改的效率（需要检查外键关系）；2、仅用于单节点数据库，不适用与分布式、集群场景；3、容易引发数据库的死锁问题，消耗性能；

#### 逻辑外键（主流

在业务层逻辑中，解决外键关联；

### 2.一对一

比如：用户和身份证，严格一一对应；

实现：

1、一对一关系，多使用单表拆分，将一张表的**基础字段** 放在一张表中，其他字段放在另一张表中，以提升操作效率；（比如，当某些基础信息被频繁查询时，就可单独列为一张基础表）

2、一对一可以视作特殊的一对多，因此在任意一方加入**外键** ，关联另外一方的主键，并且设置外键为唯一的（`UNIQUE`）即可；

### 3.多对多

如学生与课程，学生选多个课程，课程有多个学生选；此时直接两张表之间建立外键就不合适了（例如对于某个特定学生，其课程实际也是一张表了）；

实现：建立第三张**中间表** ，中间表至少包含**两个外键** ，分别关联两方主键；（对于例子，就是建立一张表，分别有学生id和课程id两个字段且均为外键，然后再有一个主键id字段）

## 二、多表查询

从多张表中查询；

**笛卡尔积** ：笛卡尔乘积是指在数学中，两个集合(A集合和B集合）的所有组合情况；在多表查询时，需要*消除无效的笛卡尔积* ；

---

分类：

- 连接查询
  - 内连接：查询A、B**交集** 部分数据；
  - 外连接：
    - 左外连接：查询**左表** 所有数据（包括两张表**交集** 部分数据）；
    - 右外连接：查询**右表** 所有数据（包括两张表**交集** 部分数据）；
- 子查询：查询嵌套查询；

### 1.内连接

|            |                                                            |
| ---------- | ---------------------------------------------------------- |
| 隐式内连接 | `select 字段列表 from 表1,表2 where 条件...;`            |
| 显式内连接 | `select 字段列表 from 表1 [inner] join 表2 on 连接条件;` |

- 查询时，直接写出返回字段名的话，由于不确定属于哪个表故会报错，因此要加上表名，*格式为`表名.字段名`*；
- 如果有数据*没有与另外一张表产生关联* ，那么这个属于就**不会被显示** ，想显示就要使用外连接查询；
- 查询时，如果表名很长可以采取起别名的方式，在from后声明即可，格式为`from 表1 别名1,表2 别名2 ...`，然后整条查询语句的其余处都必须使用**别名** ；

案例：以员工表为例，tb01是员工表，tb02是部门表；1、查询员工的姓名，及所属的部门名称（隐式内连接实现）；2、查询员工的姓名，及所属的郎门名称（显式内连接实现）；

```MySQL
-- 隐式内连接
select a.name,b.name from tb01 a, tb02 b where a.dept_id = b.id;
-- 显式内连接
select a.name,b.name from tb01 a inner join tb02 b on a.dept_id = b.id;
```

### 2.外连接

| 分类     |                                                                   |
| -------- | ----------------------------------------------------------------- |
| 左外连接 | `select 字段列表 from 表1 left [outer] join 表2 on连接条件...`  |
| 右外连接 | `select 字段列表 from 表1 right [outer] join 表2 on连接条件...` |

- 外连接既包含了特定表的所有数据，也会包含交集部分的数据；
- 即使主表中的某些数据与另一张表没有关联，采用外连接的方式也会被查询到；
- **主表** 的确定：左/右外连接，主表就是`left/right join` 左/右侧的表；
- 一般左外连接用的多，如果要左右外连接互换的话，调换下表的顺序就行；

案例：1、查询员工表*所有* 员工的姓名，和对应的部门名称（左外连接）；2、查询部门表*所有* 部门的名称，和对应的员工名称（右外连接）；

```MySQL
select a.name, b.name form tb01 a left [outer] join tb02 b on a.dept_id = b.id;

select a.name, b.name from tb01 a right [outer] join tb02 b on a.dept_id = b.id;
```

### 3.子查询

SQL语句中嵌套select语句，也称为嵌套查询；

形式：`select * from t1 where column1 = (select column1 from t2 ...);`

子查询外部的语句可以是insert/update/delete/select的任何一个，最常见的是select；

| 子查询分类 |                                           |
| ---------- | ----------------------------------------- |
| 标量子查询 | 子查询返回结果为单个值                    |
| 列子查询   | 子查询返回的结果为一列                    |
| 行子查询   | 子查询返回的结果为一行                    |
| 表子查询   | 子查询返回的结果为多行多列（**临时表**） |

子查询的核心是**步骤分解/查询分解** ；

---

#### 标量子查询

子查询返回的结果是单个值（数字、字符串、日期等）；

常用的操作符为`= <> > >= < <=`；

案例：还是员工表和部门表 1、查询教研部的所有员工信息。可以分成两个查询：查询教研部在部门表中的主键id、查询员工表，其中部门id等于主键id；2、查询在方东白入职之后的员工信息。可以分解成查询东方白的入职时间、在员工表中查询小于该时间的员工；

```MySQL
select * from tb01 where dept_id = (select id from tb02 where name = '教研部');

select * from tb01 where entrydate > (select entrydate from tb02 where name = '东方白');
```

#### 列子查询

子查询返回的结果是一列（可以是多行）；
常用的操作符：`in`、`not in`等；

案例：查询教研部和咨询部的所有员工信息，获得的主键id是一列；

```MySQL
select * form tb01 where dept_id in (select id form tb02 where name = '教研部' or name = '咨询部');
```

#### 行子查询

子查询返回的结果是一行（可以是多列）；
常用的操作符：`=`、`<>`、`in`、`not in`；

案例：查询与韦一笑的入职日期及职位都相同的员工信息；

这里也可以通过两次子查询实现，但很麻烦；更好的解决方式是把日期和职位视作一个**整体** ，语法`(entrydate,job)`，这样就可以通过一次子查询解决了；

```MySQL
select * from tb01 where (entrydate,job) = (select entrydate,job from tb02 where name = '韦一笑');
```

#### 表子查询

子查询返回的结果是多行多列，常作为**临时表** ；（比如说要查询的东西是
常用的操作符：`in` ；

案例：查询入职日期是2006-01-01之后的员工信息，及其部门名称。这里涉及到多表查询，可以分两步：第一步查询符合条件的全部员工信息，这里就是一张临时表，然后再根据这张临时表和部门表多表查询；

查询全部数据可以使用**别名** ，`别名.*`

```MySQL
select a.*,b.name form (select * from tb01 where entrydate > '2006-01-01') a , tb02 b where a.dept_id = b.id; 
```
